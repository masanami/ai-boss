# AIボス — セルフマネジメント支援アプリ (MVP)

## 概要

AIが「上司（ボス）」を演じ、ユーザーからの仕事の報告・相談を受けて優先順位や進め方を**決定の形で**指示するセルフマネジメント支援アプリ。朝会・夕会のセッションと随時チャット、macOS通知による催促で、自己管理の弱さを外部の強制力とモチベーション演出で補う。

## 背景・目的

- ユーザーは仕事の自己管理（計画・進捗管理・先延ばし防止）が苦手で、自分ひとりでは規律を維持しにくい。
- 「上司に報告する」という社会的な構造を擬似的に作ることで、締切意識と報告義務による強制力を生み出す。
- ボスが意思決定まで行うことで「何をやるか迷う」コストを削減する。ユーザーは決定に異議があれば進言でき、ボスが再裁定する。
- モチベーション維持が主目的のひとつであるため、CUIではなく**リッチなGUI**（ボスのアバター・表情・進捗の可視化）を重視する。

## ユーザーストーリー

自己管理が苦手な個人ワーカーとして、AIボスに毎日仕事の計画と進捗を報告し、優先順位の決定・催促・叱咤激励を受けることで、先延ばしせずに仕事を完遂したい。

## 機能要件

### タスク管理（内蔵）

- [ ] タスクの CRUD（タイトル・詳細・締切・優先度・ステータス: todo / in_progress / done / dropped）
- [ ] タスク一覧をボード形式（ステータス別カラム）で表示できる
- [ ] タスクには「ボスの決定・コメント」を紐付けられる（優先度や締切はボスが決定したものとして表示される）
- [ ] カテゴリ属性を持つ（MVPでは `work` 固定。将来「習慣・自己投資」等に拡張できる設計にする）

### ボスとの対話

- [ ] ボスとのチャットUI（ストリーミング表示、会話履歴の永続化）
- [ ] **朝会（計画セッション）**: 今日の予定を報告すると、ボスがタスクの優先順位・今日のノルマを決定して提示する
- [ ] **夕会（報告セッション）**: 進捗を報告すると、ボスが達成を評価し、未達の理由を確認し、翌日への持ち越しを裁定する
- [ ] **随時チャット相談**: いつでも相談でき、ボスが意思決定の形で回答する
- [ ] ボスはチャット内から直接タスクの作成・更新（優先度変更・締切設定等）を行える（tool use）
- [ ] ボスは会話時に現在のタスク一覧・直近の報告履歴をコンテキストとして参照する

### 意思決定と進言

- [ ] ボスの決定は「決定事項」として記録され、決定ログ画面で一覧できる
- [ ] ユーザーは決定に対して**進言**（異議申し立て）でき、ボスは進言を踏まえて再裁定する（維持 or 修正）
- [ ] 強制力レベルは MVP では「実質アドバイザー」: ボスは決定の形で断言するが、従うかはユーザーの自由。従わなかった場合は夕会でボスが言及する
- [ ] （将来拡張）強制力レベルを設定で変更可能にする（アドバイザー / 上書きは記録に残る / 決定は絶対）

### 催促・叱咤の通知

- [ ] 朝会・夕会の時刻（設定可能）になったら macOS 通知でセッションを促す
- [ ] 朝会・夕会が未実施のまま一定時間経過したら催促通知を送る
- [ ] 締切が近い・超過したタスクがあるとき、ボスの人格を反映した文面で通知する
- [ ] 通知クリックでアプリ（ブラウザ）が開く

### ボスの人格カスタマイズ

- [ ] 設定画面でボスの人格を調整できる: 名前、口調プリセット（厳格 / ロジカル / 熱血 など）、厳しさレベル、自由記述の追加指示
- [ ] 人格設定はチャット・通知文面の両方に反映される

### モチベーションUI

- [ ] ボスのアバターを表示し、文脈に応じて表情が変わる（通常 / 満足 / 不機嫌 / 激励 など）
- [ ] ダッシュボードに今日のノルマ達成状況（進捗ゲージ）、ボスからの今日のひとことを表示する
- [ ] 夕会での評価結果（褒め / 叱咤）が視覚的に演出される

## 非機能要件

- **プライバシー**: 業務内容を含む全データはローカル（SQLite ファイル）にのみ保存する。外部送信は Claude API への推論リクエストのみ
- **セキュリティ**: Anthropic API キーはサーバー側 `.env` にのみ保持し、フロントエンドへ渡さない・リポジトリにコミットしない
- **可用性**: 通知・スケジューラが機能するため、ローカルサーバーは常駐する前提（ログイン時自動起動は将来対応）
- **コスト**: API 呼び出しは会話・通知文面生成時のみ。モデルは設定で変更可能にし、コストを調整できるようにする

## 技術的な制約・方針

- **形態**: ローカルWebアプリ（サーバー常駐＋ブラウザUI）。将来 Tauri 等でのデスクトップ化を妨げない構成にする
- **フロントエンド**: Vite + React + TypeScript
- **バックエンド**: Node.js + Hono（REST + SSE ストリーミング）、node-cron によるスケジューラ
- **DB**: SQLite（better-sqlite3）
- **LLM**: Claude API（`@anthropic-ai/sdk`）。デフォルトモデル `claude-sonnet-5`、設定で変更可能
- **通知**: macOS 通知センター（`terminal-notifier` 優先、未導入時は `osascript` フォールバック）
- **対象OS**: macOS のみ（ユーザー環境）
- **リポジトリ構成**: モノレポ（`server/` と `web/`）

## 画面・UI設計方針（暫定 — ユーザー確認前の推奨案）

> 以下はユーザー未確認の暫定決定。実装着手前に変更可。細かいレイアウトは実装フェーズでモックを見ながら調整する。

- **メイン画面構成**: チャット中心。ボスとの対話が常に主役で、右サイドパネルに今日のタスクと進捗ゲージを常時表示。ダッシュボード・タスクボード・決定ログ・設定は左ナビで切り替え

```text
+--------+------------------------+----------+
| ナビ    |  [ボスのアバター]      | 今日の   |
|        |                        | タスク   |
| チャット|  ボス: 今日の優先は    | ■ 資料   |
| タスク |      A案件だ。        | □ メール |
| 決定ログ|  自分: 了解です       | □ レビュー|
| 設定   |                        |          |
|        |  [入力欄___________]  | 進捗 60% |
+--------+------------------------+----------+
```

- **デザイントーン**: シックなオフィス風（ダーク基調）。「上司の執務室」の緊張感を演出しつつ、褒め演出時は暖色のアクセントで報われ感を出す
- **アバター**: 表情差分付きのAI生成イラストを数種類プリセット同梱（通常 / 満足 / 不機嫌 / 激励）。実装を SVG やドット絵に差し替えられるよう、アバターは「表情キー → 画像」のマッピングとして抽象化する（将来のスキンカスタマイズ [future-ideas.md](./future-ideas.md) への布石）

## クリティカル設計決定

### APIキー・機密データの取り扱い

- **採用案**: Anthropic API キーはサーバー側の `.env`（gitignore 対象）にのみ保持。Claude API 呼び出しはすべてバックエンド経由で行い、フロントエンドはローカルバックエンドとのみ通信する
- **理由**: キーがブラウザに露出せず、単一ユーザー・ローカル環境で最も簡潔かつ安全
- **代替案**: OS キーチェーン保管 — 単一ユーザーのローカルツールには過剰で実装コストが高いため却下。フロントから直接 API 呼び出し — キー露出と CORS の問題で却下
- **影響範囲**: `server/.env`、`server/` の Claude クライアントモジュール

### 外部システム連携（Claude API）

- **採用案**: バックエンドに Claude クライアントを集約。ストリーミング応答は SSE でフロントへ中継。リトライは指数バックオフで最大2回、タイムアウトはリクエスト単位 120 秒。ボスによるタスク操作は tool use（タスク CRUD ツール定義）で実現
- **理由**: ストリーミングは体感速度＝モチベーションUIの要。tool use により「ボスが直接タスクを動かす」体験を安全に実現できる
- **代替案**: 応答完了後に一括返却 — 長考時の体験が悪く却下
- **影響範囲**: `server/` の LLM クライアント・チャット API・ツール実行層

### DBスキーマ（新規）

- **採用案**: SQLite に以下のテーブルを新設
  - `tasks`: id, title, description, category, priority, due_at, status, boss_comment, created_at, updated_at, completed_at
  - `sessions`: id, type (morning / evening / adhoc), started_at, ended_at, summary
  - `messages`: id, session_id, role (user / boss), content, created_at
  - `decisions`: id, session_id, task_id (nullable), content, rationale, status (active / revised / withdrawn), created_at
  - `appeals`: id, decision_id, content, verdict (upheld / revised), created_at（進言と再裁定の記録）
  - `settings`: key-value（ボス人格、朝会・夕会時刻、モデル名、強制力レベル等）
  - `notifications`: id, type, body, sent_at（催促の重複送信防止・履歴用）
- **理由**: セッション（朝会・夕会・随時）を第一級の概念にすることで、報告フローと決定ログが自然に表現できる
- **代替案**: 会話を単一スレッドで持つ — 朝会・夕会の区切りや日次評価が表現しにくく却下
- **影響範囲**: `server/` の DB 層（マイグレーションは初期スキーマのみ）

## 機能全体の設計

### アーキテクチャ決定

- モノレポ構成: `server/`（Hono API + スケジューラ + 通知 + SQLite）と `web/`（Vite + React SPA）
- サーバーが唯一の状態保持者。フロントは REST + SSE のみで通信し、ロジックを持たない
- ボスの人格は「システムプロンプト生成器」に集約: 設定（口調・厳しさ・自由記述）＋現在のコンテキスト（タスク一覧・直近の決定・時間帯）からプロンプトを組み立てる。チャットと通知文面生成の両方が同じ生成器を使う
- スケジューラ（node-cron）は毎分チェック方式: 朝会・夕会時刻、未実施の催促、締切接近・超過を判定し、`notifications` テーブルで重複送信を防ぐ
- 将来拡張ポイント: タスクソースを interface 化し Google Calendar 連携を追加できるようにする / カテゴリ追加で習慣管理に拡張 / 強制力レベルの段階追加
- その他のアイデアは [future-ideas.md](./future-ideas.md) にバックログとして管理する（MVPスコープ外）

### IF / API（主要エンドポイント）

```text
GET    /api/tasks              タスク一覧
POST   /api/tasks              タスク作成
PATCH  /api/tasks/:id          タスク更新
GET    /api/sessions           セッション一覧（履歴）
POST   /api/sessions           セッション開始 (type: morning|evening|adhoc)
POST   /api/sessions/:id/messages   発言送信 → SSE でボス応答ストリーム
GET    /api/decisions          決定ログ
POST   /api/decisions/:id/appeals   進言 → ボスの再裁定を返す
GET/PUT /api/settings          設定（ボス人格・時刻・モデル等）
GET    /api/dashboard          今日のノルマ・進捗・ひとこと
```

### 実装計画（チケット分解の見通し）

1. **基盤**: モノレポ雛形、SQLite スキーマ、Hono サーバー、Vite+React 雛形
2. **タスク管理**: CRUD API + タスクボード UI
3. **ボス対話基盤**: Claude クライアント、人格プロンプト生成器、チャット UI（SSE）、tool use によるタスク操作
4. **セッションフロー**: 朝会・夕会のガイド付きフロー、決定の記録
5. **決定ログと進言**: 決定一覧 UI、進言 → 再裁定フロー
6. **スケジューラ・通知**: node-cron、macOS 通知、催促ロジック
7. **ダッシュボード・モチベーションUI**: アバター表情、進捗ゲージ、評価演出
8. **設定画面**: ボス人格カスタマイズ、時刻・モデル設定

## 受入基準

- [ ] 朝会でその日の予定を報告すると、ボスが優先順位付きの今日のノルマを決定として提示し、タスクに反映される
- [ ] 夕会で進捗を報告すると、ボスが達成/未達を評価し、未達タスクの扱いを裁定する
- [ ] 随時チャットで相談すると、ボスが決定の形で回答し、必要ならタスクを直接作成・更新する
- [ ] ボスの決定が決定ログに残り、進言すると再裁定（維持 or 修正）が返って記録される
- [ ] 設定した朝会・夕会時刻に macOS 通知が届き、クリックでアプリが開く
- [ ] 締切超過タスクがあるとボス人格を反映した催促通知が届く
- [ ] 設定画面でボスの口調プリセット・厳しさを変えると、以後の応答と通知文面に反映される
- [ ] ダッシュボードに進捗ゲージとボスのひとことが表示され、アバターの表情が文脈で変化する
- [ ] API キーが `.env` 以外（フロントエンド・リポジトリ）に存在しない
