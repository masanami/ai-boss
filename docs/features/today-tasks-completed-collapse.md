# 今日のタスク一覧で完了タスクを末尾に畳む

## 概要

サイドパネル「今日のタスク」（`web/src/TodaySummary.tsx`）の一覧から、今日完了したタスクを末尾の折りたたみセクションへ移す。既定は折りたたみ、ヘッダを押すと展開する。完了が積み上がる日ほど一覧が伸びてスクロールを圧迫する問題（#245）を、集計側の定義に触れずに表示層だけで解く。

## 背景・目的

サイドパネル「今日のタスク」の対象は `web/src/today-tasks.ts` の `selectTodayTasks` が決めており、`todo` / `in_progress` / `paused` に加えて**今日（ローカル日付）完了したタスク**を含む。並び替えはせずサーバの返却順（`created_at ASC, id ASC`）を保つため、**完了タスクは未完了タスクの間に作成順のまま散在する**。完了が積み上がる日ほど一覧が伸び、サイドパネル（`CheckinPanel` と 1 つのスクロール領域を共有）のスクロールが増える。

単純に完了タスクを対象集合から外せない理由が 2 つある。

1. `selectTodayTasks` は表示用フィルタではなく、**サイドパネルの進捗ゲージのデータ源そのもの**である。`TodaySummary.tsx` は戻り値から `done` / `total` / `percentage` を自前計算して「3 / 5 件完了（60%）」を描画している。集合から完了を外すとゲージが `3/5` → `0/2` に壊れる。
2. `selectTodayTasks` の対象定義はサーバのノルマ進捗（`server/src/dashboard/progress.ts` の `isTargetTask`）と条件が 1:1 で対応しており、doc コメントで「同じ定義」と明示されている。表示の都合で集計側の定義を動かさない。

一方、**表示層で完了タスクを畳んでも進捗の分子は消えない**（一覧のすぐ下の進捗セクションが「3 / 5 件完了（60%）」を出し続ける）。消えるのは「**どのタスクを終えたか**」＝ ■ マーカーによる達成の可視化であり、これは README の「モチベーション演出」に当たる中核価値である。したがって**完全に隠すのではなく畳む**。

## ユーザーストーリー

サイドパネルで今日の進み具合を確認するオーナーとして、完了したタスクを畳んだ一覧を使って、**残っている仕事だけをスクロールなしで把握**したい。畳んだ完了タスクは必要なときに展開して達成を確認できる。

## 機能要件

- [ ] サイドパネル「今日のタスク」の一覧は、既定では未完了タスク（`todo` / `in_progress` / `paused`）のみを表示する
- [ ] 今日完了したタスクは一覧の末尾に置いた折りたたみセクションへまとめる
- [ ] 折りたたみセクションのヘッダは完了件数のみを示す（比率は既存の進捗セクションが担う）
- [ ] ヘッダを押すと完了タスクが展開表示される
- [ ] 展開中にヘッダをもう一度押すと折りたたまれる
- [ ] 今日完了したタスクが 0 件のときは折りたたみヘッダを表示しない
- [ ] 展開状態は永続化せず、再マウント時は既定（折りたたみ）に戻る
- [ ] 今日のタスクが 1 件も無いときは「今日のタスクはまだありません」を表示する（既存の振る舞いを維持）
- [ ] 未完了タスクが 0 件で今日完了したタスクが 1 件以上のときは「今日のタスクはすべて完了しました」を表示する
- [ ] 未完了タスクが 1 件以上のときは上記どちらのメッセージも表示しない
- [ ] 未完了タスクが 0 件で今日完了したタスクが 1 件以上のときも、完了セクションのヘッダと折りたたみは通常どおり表示する

## 技術的な制約・方針

- 変更対象: `web/src/today-tasks.ts`（純粋関数の追加のみ）、`web/src/TodaySummary.tsx`、`web/src/TodaySummary.css`、`web/src/TodaySummary.test.tsx`、`web/src/today-tasks.test.ts`（追加のみ）
- **変更しない**: `server/src/dashboard/progress.ts`、`selectTodayTasks` のシグネチャ・戻り値・doc コメント、`web/src/TaskBoard.tsx`、`web/src/CheckinPanel.tsx`、ダッシュボードのメイン領域
- 折りたたみは既存 idiom を踏襲する: `<button type="button" aria-expanded={expanded}>` ＋条件レンダリング（`web/src/CheckinPanel.tsx` の「時刻を指定して記録」トグルと同じ形）。`<details>` はこのリポジトリで未使用のため導入しない
- テストの固定時刻は `new Date(y, m, d, h)` 由来で組み、TZ 非依存にする（UTC 文字列固定は不可）。日付境界に触るため `npm run test:tz` も通す

## クリティカル設計決定

> Issue #245 の論点 1〜4 に対する決定。後続の実装はこの決定に従い、独自判断で逸脱しない。

### 1. 完了タスクの扱い（隠す / 畳む / 末尾へ送る）

- **採用案**: 末尾へ送り、既定は折りたたむ
- **理由**: (1) 完全に隠すと ■ マーカーによる「どのタスクを終えたか」の可視化が失われる。これは README の「モチベーション演出」（表情が変わるボスのアバター、進捗ゲージ、褒め・叱咤の演出）に当たる中核価値である。(2) #252（今日の活動ログを「既定は最新 N 件＋全件表示する」にする）と共有できる disclosure の作法が 1 つ残る
- **代替案**:
  - 完全に隠す — 却下。実装は最小で進捗の分子も消えない（進捗セクションが担保する）が、達成の可視化がゼロになり、#252 に再利用できるパターンも残らない
  - 末尾へ送るだけで畳まない — 却下。並びは自然になるが、完了が積み上がる日ほど一覧が伸びるという要望の核心が解決しない
- **影響範囲**: `TodaySummary.tsx` の一覧描画のみ。**`TaskBoard`・ダッシュボードのメイン領域・`CheckinPanel` には及ばない**

### 2. #252 との UI パターンの揃え方

- **採用案**: 共通にするのは **disclosure の作法だけ**（`<button type="button" aria-expanded>` ＋条件レンダリング、ラベルに残件数を添える書き方）とし、共有コンポーネントは作らない
- **理由**: YAGNI。本件は「完了／未完了でグループ化して畳む」、#252 は「既定は最新 N 件で切り詰める」で切り詰め軸が異なる。1 例しかない段階で抽象を作らない
- **代替案**: 共有コンポーネントを 1 つ作って両方をそれで実装する — 却下（上記の理由）。**#252 の実装時に 2 例目を見てから共通化を検討する**
- **影響範囲**: 本仕様では抽出を行わない。#252 は本仕様のスコープ外

### 3. 進捗表示との整合

- **採用案**: 折りたたみヘッダは**件数のみ**を出す（例: 「完了したタスク（3 件）」）。比率は既存の進捗セクションに任せる。完了 0 件のときはヘッダごと出さない
- **理由**: 一覧のすぐ下に「3 / 5 件完了（60%）」が出続けるため、ヘッダにも比率を出すと同じ数字が縦 2 行以内に重複する。ヘッダの件数だけで折りたたみの中身の見当はつく
- **代替案**: ヘッダにも「3/5 完了」を出す — 却下（上記の重複）
- **影響範囲**: 折りたたみヘッダの文言のみ。**既存の「3 / 5 件完了（60%）」の表示と計算（`TodaySummary.tsx` の `done` / `total` / `percentage` 導出）は変更しない**

### 4. `TaskBoard` の「完了」列

- **採用案**: 対象外とする
- **理由**: #245 が指すスクロールはサイドパネル（`.app-side-panel` が `overflow-y: auto` を持つ）で、`TaskBoard` は別領域である。対象外にすることで `TaskBoard.test.tsx` を無改変で通せる
- **代替案**: 同時に対象にする — 却下。`TaskBoard` の「完了」列が日付条件なしの全件を描画して長期的に肥大する件は実在するが、要望とは別問題であり、**別 Issue として独立に扱う**（本仕様の実装チケットとは紐づけない）
- **影響範囲**: `TaskBoard.tsx` / `TaskBoard.test.tsx` はいずれも無改変

### 5. `progress.ts` と定義を揃えた既存の約束の扱い

- **採用案**: `selectTodayTasks` は**完全に無改変**とし、その戻り値を受ける別の純粋関数 `partitionTodayTasks(tasks) → { pending, done }` を `web/src/today-tasks.ts` に**併置**する。表示層はそれを使う
- **理由**: `selectTodayTasks` はサイドパネルの進捗ゲージのデータ源そのものであり、対象集合を変えるとゲージが壊れる（背景・目的の 1）。関数を分けることで、`progress.ts` との 1:1 対応を述べた doc コメントと既存テスト 6 件をそのまま残せる。グルーピングは表示の関心であり、集計側と揃えてある関数に載せると「同じ定義」の主張が読みにくくなる
- **代替案**:
  - `selectTodayTasks` の戻り値にグルーピング情報を持たせる — 却下。対象集合は変わらないが、`TodaySummary` の `done` / `total` 計算と既存テスト 6 件がすべて同時に書き換わる
  - 対象集合そのものを変える — 却下。サイドパネルのゲージが壊れ、`progress.ts` との対応も切れる
- **影響範囲**: `web/src/today-tasks.ts` への関数追加のみ。**`server/src/dashboard/progress.ts` には触れない**

### 6. 全件完了時のメッセージの位置づけ

- **採用案**: 「今日のタスクはすべて完了しました」は**静的 UI テキスト**として実装する。LLM 生成にせず、ボスの口調プリセット（`persona-prompt.ts` の口調 4 プリセット × 厳しさ 5 段階 × 自由記述）を通さない。演出（アニメーション・アバター表情の変化・効果音等）も加えず、テキストの出し分けのみとする
- **理由**: ボスの人格・トーンに関わる範囲へ本課題を広げない、という境界をここで固定する。文言が固定されることでテストが文字列で担保できる
- **代替案**: ボスのひとことを LLM で生成する／完了演出を加える — 却下。本課題（一覧のスクロール圧迫）のスコープ外であり、ボスの人格設計に踏み込むため別途要件化が要る
- **影響範囲**: `TodaySummary.tsx` の空表示分岐のみ。`persona-prompt.ts`・アバター・通知には及ばない

## IF / API

```ts
// web/src/today-tasks.ts に併置する純粋関数（selectTodayTasks は無改変）
export function partitionTodayTasks(tasks: Task[]): {
  pending: Task[]; // status が todo / in_progress / paused
  done: Task[];    // status が done
};
```

- 入力は `selectTodayTasks` の戻り値を想定する（`dropped` と過去日完了は既に除外済み）
- `pending` / `done` それぞれの中で**入力順を保つ**。新たな並び替え規則を発明しない
- 入力配列を破壊しない
