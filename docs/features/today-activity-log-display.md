# 今日の活動ログの表示を整える（行の折り返しと既定件数）

## 概要

サイドパネル「今日の活動」（`web/src/CheckinPanel.tsx` の `.checkin-activity-list`）の表示を 2 点整える。(1) 1 件の行が狭い幅で 1 文字ずつ縦に積まれる崩れを CSS で解消する。(2) 既定では最新 20 件だけを表示し、「全件表示する（全 N 件）」ボタンで全件へ展開できるようにする。サーバ（`server/`）は無改変で、表示層だけで解く。

## 背景・目的

### 1. 1 行が縦長に折り返す

活動ログ 1 件は `<li>` の中に最大 4 つの `<span>`（時刻／操作ラベル／タスク名／ひとこと）が並ぶ。現在の CSS は 3 プロパティだけである（`web/src/CheckinPanel.css:108-112`）。

```css
.checkin-activity-list li {
  display: flex;
  gap: 0.4rem;
  color: var(--color-text);
}
```

`flex-wrap` も、各 span の `flex-shrink` / `white-space` / `min-width` も指定が無い。flex アイテムは既定で `flex-shrink: 1` かつ自動最小サイズ（`min-width: auto` ＝ min-content）を持ち、**日本語の min-content は 1 文字幅**である。4 つの合計幅が行幅を超えると 4 つとも自動最小サイズまで縮み、結果として **1 文字ずつ縦に積まれる**。

**発生条件は画面サイズではなく「その行の内容の長さ」である。** サイドパネルの幅はウィンドウ幅に追随しない。#253 完了後の現在、幅は**オーナーがドラッグで変えられる可変値**で、`web/src/side-panel-width.ts:9-11` が `SIDE_PANEL_MIN_WIDTH = 280` / `SIDE_PANEL_MAX_WIDTH = 420` / `SIDE_PANEL_DEFAULT_WIDTH = 280` を定め、`AppLayout.tsx:134` がインラインスタイルで `--side-panel-width` を上書きする（`index.css:20` の `280px` はフォールバック値）。`.app-side-panel` の `padding: 1rem` と左ボーダー 1px を引くと、1 行に使える実効幅は **247px（最小）〜 387px（最大）** のレンジになる。

したがって直すべき条件は「特定の画面幅で直す」ではなく、**幅がいくつであっても、どんな長さの内容でも行が崩れないようにする**ことである。

### 2. ログが長くなりすぎる

`GET /api/activity/today` は当日分を**全件返す**（`server/src/activity/activity-routes.ts:18-31`。件数上限もページングも無い）。フロントも `events.map(...)` で**全件そのまま描画**する（`CheckinPanel.tsx:570`）。

件数の主因は**チャットである**。ボスとのチャット発言 1 通ごとに `chat_message` の活動イベントが 1 行増える（`server/src/sessions/chat-messages-route.ts:259`）。チャットは本アプリの主要な相談導線であり、チャット主体の日は容易に 50〜100 件規模へ伸びる。サイドパネルは `CheckinPanel` と「今日のタスク」で 1 つのスクロール領域（`.app-side-panel { overflow-y: auto }`）を共有するため、活動ログが伸びるほどスクロールを圧迫する。

一方、活動ログは「今日これだけ動いた」という手応えを与える面も持ち、これは README が挙げるモチベーション演出に当たる中核価値である。そのため**単に切り詰めるだけにせず、総件数を全件表示ボタンのラベルに出して総量が読めるようにする**（決定 3）。

## ユーザーストーリー

サイドパネルで今日の動きを振り返るオーナーとして、**幅をどう変えても崩れない活動ログ**を、**既定は直近だけに絞られた短い一覧**として読みたい。古い分まで遡りたいときは「全件表示する」で開ける。

## 機能要件

- [ ] 活動ログの 1 件が、サイドパネルの最小幅（280px）でも 1 文字ずつ縦に積まれない
- [ ] 時刻と操作ラベルは行が折り返しても縮まず、そのまま読める
- [ ] 長いタスク名・長いひとことは省略されず、次の行へ折り返して全文が読める
- [ ] 活動が 21 件以上あるとき、既定では新しい側の 20 件だけを表示する
- [ ] 活動が 21 件以上あるとき、一覧の直前に「全件表示する（全 N 件）」ボタンを表示する
- [ ] 全件表示ボタンを押すと当日の活動が全件表示される
- [ ] 展開中に全件表示ボタンをもう一度押すと既定（最新 20 件）へ戻る
- [ ] 活動が 20 件以下のときは全件表示ボタンを表示しない
- [ ] 展開状態はチェックイン記録後の再取得をまたいで保持され、再マウント時は既定（折りたたみ）へ戻る
- [ ] 活動が 0 件のときは「まだ活動はありません」を表示する（既存の振る舞いを維持）

## 技術的な制約・方針

- **変更対象**: `web/src/CheckinPanel.tsx`、`web/src/CheckinPanel.css`、`web/src/CheckinPanel.test.tsx`（追加・既存は無改変）
- **変更しない**: `server/` 配下すべて（とくに `server/src/activity/activity-routes.ts` と `activity-routes.test.ts`）、`web/src/TodaySummary.tsx`、`web/src/TaskBoard.tsx`、`web/src/AppLayout.tsx`、`web/src/side-panel-width.ts`
- **切り詰めは 1 本の `<ul>` 内で行う**（`<ul>` を 2 本に分割しない）。既存テスト `web/src/CheckinPanel.test.tsx:319, 347` が `screen.findByRole("list")` を**単数形**で使っており、`<ul>` が 2 本になると "found multiple elements" で失敗するため
- **全件表示ボタンに `checkin-primary-button` クラスを付けない**。`web/src/CheckinPanel.test.tsx:1900-1905`（#244）が「描画中の全 button のうち `checkin-primary-button` を持つもの」を `["着手", "完了", "一時停止", "休憩"]` で**全数固定**しており、付けると失敗するため。全件表示ボタンは補助操作であり、リンク風の `.checkin-time-input-toggle button` と同格
- 折りたたみは既存 idiom を踏襲する: `<button type="button" aria-expanded={expanded}>` ＋条件レンダリング（`web/src/CheckinPanel.tsx:394-403` の「時刻を指定して記録」トグルと同じ形）。`<details>` はこのリポジトリで未使用のため導入しない
- **共通の折りたたみコンポーネント・共通フックを新設しない**（#245 決定 2 の YAGNI を踏襲）
- 既定表示件数は定数（`UPPER_SNAKE_CASE`）として `CheckinPanel.tsx` に置く（CLAUDE.md の命名規則）
- 新規テストで活動イベントを 21 件以上作る場合、`created_at` は `new Date(y, m, d, h, m)` 由来で組んで TZ 非依存にする（UTC 文字列固定は不可）
- 本仕様の CSS に関する px 見積り（時刻 ≈35px・操作ラベル最大 ≈77px 等）は `0.8rem ≒ 12.8px` からの算術見積りであり、**ブラウザ実測ではない**。実測は実装後の `/demo` で行う

## クリティカル設計決定

> Issue #252 の論点 1〜8 に対する決定。後続の実装はこの決定に従い、独自判断で逸脱しない。

### 1. 行の折り返し方（`flex-wrap` か `flex-shrink: 0` か）

- **採用案**: 併用する。`.checkin-activity-list li` に `flex-wrap: wrap` を足し、時刻・操作ラベルの span に `flex-shrink: 0`、タスク名・ひとことの span に `min-width: 0` を与える。**操作ラベルに `white-space: nowrap` は付けない**
- **理由**: 主たる修正は `flex-wrap: wrap` である。折り返しを許すと、max-content が行幅を超える長いタスク名・ひとことは**自分だけの行**へ送られ、そこで行幅いっぱいを使って通常どおり折り返せる。折り返しが無い現状では 4 つの span が同一行に留まり、全員が自動最小サイズ（日本語では 1 文字幅）まで縮むため 1 文字ずつ積み上がる。`flex-shrink: 0` は、同一行に残った場合の縮みを可変列（タスク名・ひとこと）側に吸収させ、時刻と操作ラベルの視認性を常に保つための固定である。`min-width: 0` は、その可変列が縮む側であることを明示し、自動最小サイズ（1 文字幅）の下限を外す
- **代替案**:
  - `flex-wrap: wrap` のみ — 却下。長い行は救えるが、時刻・操作ラベルが縮み得る余地が残り「時刻と操作は常に読める」を保証できない
  - `flex-shrink: 0` のみ — 却下。4 つの span が必ず 1 行に留まるため、最小幅 280px では可変列の取り分が枯渇して溢れる
  - 操作ラベルに `white-space: nowrap` も付ける — 却下。`flex-shrink: 0` によりラベルは max-content 幅で据わるので追加の効果が無く、宣言だけが増える（KISS）
- **影響範囲**: `web/src/CheckinPanel.css` の `.checkin-activity-list li` と、新設する span 用クラスのみ。`CheckinPanel.tsx` は span に `className` を付けるだけで描画ロジックは変えない。**jsdom は CSS を適用せずレイアウトも行わないため、この決定は自動テストで検証できない**（決定 7）

### 2. 長いタスク名の扱い（省略か折り返しか）

- **採用案**: 省略せず折り返す。`text-overflow: ellipsis` と `title` 属性はいずれも**導入しない**
- **理由**: (1) `text-overflow: ellipsis` も `title` 属性も `web/src` に前例が無く（既存の長文対策は `WorkLogView.css:25` / `DailyReportView.css:68` の `overflow-wrap: break-word` のみ）、本件のためだけに新しい idiom を持ち込む必要が無い。(2) `title` によるツールチップはキーボード操作・タッチで到達できないため、「全文を辿れる」担保として弱い。(3) サイドパネルは既に `overflow-y: auto` を持ち縦スクロールが許容されているので、1 行に押し込む動機が薄い。加えて決定 3 で件数を絞るため、1 件あたりの高さが増えても一覧全体の総量は制御できる
- **代替案**: 1 行省略（`overflow: hidden; white-space: nowrap; text-overflow: ellipsis`）＋ `title` で全文 — 却下（上記 3 点）。なお採る場合は flex アイテムの自動最小サイズを外す `min-width: 0` が必須で、これが無いと省略が効かない
- **影響範囲**: `CheckinPanel.css` のみ。`CheckinPanel.tsx` に `title` 属性を足す変更は**発生しない**

### 3. 既定表示件数 N と、総件数の見せ方

- **採用案**: N = **20**・コード内定数で固定する。設定 UI は作らない。あわせて全件表示ボタンのラベルに総件数を出し、**「全件表示する（全 N 件）」**の形（例: 全 47 件なら「全件表示する（全 47 件）」）とする
- **理由**: 件数の主因はチャット発言であり（背景・目的の 2）、チャット主体の日は容易に 50〜100 件規模へ伸びるため、既定を絞る価値がある。一方で切り詰めは「今日これだけ動いた」という手応え（README のモチベーション演出）を削るため、総件数をラベルに出して総量を明示し、これを打ち消す。20 は「直近の流れを追う」用途に足り、かつ最小幅 280px でも一覧が過大にならない値として置く
- **代替案**:
  - N = 10 — 却下。チャットが数通挟まるだけでタスク操作の履歴が既定表示から消える
  - N = 50 — 却下。チャット主体でない日にはほぼ全件表示と変わらず、切り詰める意味が薄い
  - 設定 UI で可変にする — 却下。`SettingsView`・永続化・API を巻き込む割に得るものが無い（YAGNI）
- **影響範囲**: `CheckinPanel.tsx` の定数 1 つとラベル文言。ラベル文言は受入基準としてテストで固定する。既存テストの活動フィクスチャはいずれも 20 件以下（ファイル内の `makeEvent(` は全 17 箇所、最大でも 1 件のフィクスチャ）なので、**既存テストに全件表示ボタンは現れず、既存の assert も既存コメントも壊れない**

### 4. 展開状態の保持範囲

- **採用案**: 素の `useState` 1 個で持つ。**再取得（refetch）をまたいでは保持され、再マウントでのみ既定（折りたたみ）へ戻る**
- **理由**: 再取得のたびに畳むには専用の `useEffect` を追加で書く必要があり、しかも「全件を開いて眺めている最中にチェックインを記録したら勝手に畳まれる」という劣った挙動になる（`CheckinPanel` はチェックイン成功時に活動を再取得する）。追加コードを書いて挙動を悪くする形になるため採らない
- **先行仕様との関係**: #245（`docs/features/today-tasks-completed-collapse.md`）の「展開状態は永続化せず、再マウント時は既定へ戻る」と**矛盾しない**。#245 が定めているのは再マウント時の挙動であり、refetch については何も定めていない。本件も再マウント時は既定へ戻る
- **代替案**: 再取得のたびに畳む — 却下（上記）
- **影響範囲**: `CheckinPanel.tsx` の `useState` 1 個。`localStorage` 等の永続化は行わない

### 5. 切り詰めをフロントで行うかサーバで行うか

- **採用案**: フロントの `slice` のみ。`GET /api/activity/today` は当日分を全件返すまま**無改変**とする
- **理由**: (1) 全件表示ボタンを押した瞬間に全件が必要になるため、API 側を絞ると 2 回目の取得が要るだけで往復が増える。(2) ローカル SQLite・シングルユーザー・当日分限定で件数は有界であり、全件取得の負荷は問題にならない。(3) `activity-routes.ts` とその既存テスト（昇順・半開区間の契約）に一切触れずに済む
- **代替案**: API に `limit` クエリを足す — 却下（上記）
- **影響範囲**: `server/` 配下は完全に無改変

### 6. #245 との UI パターンの揃え方と、ボタンの位置

- **採用案**: disclosure の作法（`<button type="button" aria-expanded>` ＋条件レンダリング ＋ ラベルに件数を添える）は #245 と揃える。**共有コンポーネント・共有フックは作らない**。ただし**ボタンの位置は一覧の「上」に置く**（#245 は一覧の「下」）
- **理由**: 活動ログは昇順（古い順）で、最新が一番下に来る（`server/src/activity/activity-events-repository.ts:87` の `ORDER BY created_at ASC, id ASC`。`activity-routes.test.ts:39` が契約として固定し、フロントは並べ替えない）。したがって「最新 20 件」とは末尾 20 件であり、**切り落とされるのは一覧の上（古い側）**である。隠れているものが上にある以上、それを開くボタンも上に置くのが自然で、下に置くと操作と結果の位置が食い違う。共有コンポーネントを作らないのは #245 決定 2 の YAGNI をそのまま踏襲するため（本件は「既定は最新 N 件で切り詰める」、#245 は「完了／未完了でグループ化して畳む」で切り詰め軸が異なる）
- **代替案**:
  - 一覧を降順（最新が上）に変え、#245 と同じく一覧の下にボタンを置く — 却下。表示順はオーナーが見慣れた既存の振る舞いであり、本 Issue は「表示を整える」であって並び順の変更を求めていない（Non-goals に再掲）
  - 昇順のままボタンを下に置く — 却下。上に隠れているものを開くボタンが下にあることになり直感に反する
- **影響範囲**: `CheckinPanel.tsx` の描画順のみ。#245 の実装（`TodaySummary.tsx`）には及ばない

### 7. 受入基準を「テストで検証する項目」と「目視に委ねる項目」に分ける

- **採用案**: 決定 1・2（折り返し・省略しないこと）に関する受入基準は**すべて目視（`/demo`）側**に置き、自動テストでは扱わない。テストで固定するのは件数・DOM 構造・`aria-expanded`・ラベル文言に限る
- **理由**: `web/vite.config.ts` の test 設定は `environment: "jsdom"` のみで CSS 処理の設定を持たず、Vite はテスト時に CSS を適用しない。加えて jsdom はレイアウトを行わないため、幅・折り返し・要素の実寸はいずれも観測できない。クラス名の付与を assert しても「崩れないこと」の担保にはならず、緑のまま未担保になる
- **代替案**: Playwright 等で視覚回帰テストを入れる — 却下。本課題のために E2E 基盤の判断を持ち込むのは過剰であり、`/demo` によるオーナーの目視で足りる
- **影響範囲**: 受入基準の書き分けのみ。テスト基盤（`web/vite.config.ts`・`vitest.setup.ts`）は無改変

### 8. 低情報な `chat_message` 行の扱い

- **採用案**: 本仕様では**何もしない**。`chat_message` も従来どおり活動ログに表示する
- **理由**: 本課題のスコープは「表示レイアウトと件数」であり、**何を見せるかの取捨は別の判断**である。表示対象を変えると活動ログの意味自体が変わり、別途要件化が要る
- **代替案**: `chat_message` を表示から除外する／連続する `chat_message` を集約する — いずれも却下（上記）。ただし将来の検討として残す（下記）
- **影響範囲**: 無し（現状維持）

## Non-goals（今回やらないこと）

- **活動ログの並び順を変えない。** 昇順（古い順・最新が下）という既存の振る舞いをそのまま維持する（決定 6）
- **`server/` を変更しない。** `GET /api/activity/today` は当日分を全件・昇順で返すまま（決定 5）
- **サイドパネルの幅の仕組みに触れない。** 可変幅は #253 で完了済みであり、本件は「幅がいくつであっても崩れない」側だけを担う
- **`web/src/TodaySummary.tsx`（#245）・`web/src/TaskBoard.tsx`（#428）には手を出さない。** #245 とは disclosure の作法だけを揃え、共通化は行わない
- **表示対象の取捨（`chat_message` の扱い）を変えない**（決定 8）

### 将来の検討（本仕様では扱わない）

チャット発言は 1 通ごとに `chat_message` イベントを生み、これらは `task_id` も `note` も持たないため「09:20 チャット発言」という低情報な行として並ぶ。チャット主体の日は既定 20 件の枠がチャットで埋まり、**本来見たいタスク操作の履歴が既定表示から押し出される**可能性がある。実運用でこれが問題になった場合、`chat_message` の除外・集約（「チャット発言 ×5」等）・種別フィルタのいずれかを別 Issue として検討する。本仕様では現状維持とする（決定 8）。
