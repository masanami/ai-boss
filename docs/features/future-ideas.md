# 将来アイデア（バックログ）

> MVP のスコープ外だが忘れたくないアイデア置き場。優先度は未定。実装する際は `/define-feature` で個別に要件化する。

## ボスのスキンをカスタマイズ

- ボスのアバターの見た目（キャラクターデザイン・服装・スタイル）を変更できる
- 人格カスタマイズ（口調・厳しさ）とは独立した「見た目」のカスタマイズ
- 検討事項: スキン素材の調達方法（プリセット同梱 / 画像アップロード / AI生成）

## ボス設定の export / import

- ボスの人格・スキン・運用設定（朝会夕会時刻など）をファイルとして書き出し・取り込みできる
- ユースケース: バックアップ、機材移行、他ユーザーと「ボス」を共有する
- 検討事項: フォーマット（JSON想定）、APIキー等の機密は含めない

## OS アクティビティ連携による自動サボり検知

- MVP のサボり検知（タスク操作＋チェックイン申告）を、アクティブアプリ・ブラウザ履歴等の OS シグナルで自動化・高精度化する
- 例: エディタ/ターミナルがアクティブ → 作業中と推定、SNS・動画サイトが長時間アクティブ → 脱線と推定
- 検討事項: 「全データはローカルのみ・外部送信は Claude API のみ」のプライバシー方針との整合（収集範囲・保存期間・LLM へ渡す粒度の設計が必要）。macOS の画面収録・アクセシビリティ権限
- 経緯: 2026-07-05 コンセプト深掘りで検討し、プライバシー設計の再検討が必要なため MVP では見送り

## 同僚とのブレイクタイム

- 休憩時間に「同僚」と雑談できる場を設ける
- 案A: AIが同僚キャラを演じる（ローカル完結、実装は容易）
- 案B: 実際の利用者同士がコミュニケーションできる（要サーバー・アカウント基盤・モデレーション。アーキテクチャがローカル完結前提から大きく変わるため要注意）
- 検討事項: MVPは完全ローカル・シングルユーザー設計のため、案Bはインフラ・プライバシー方針の再検討が必要
