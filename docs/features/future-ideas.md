# 将来アイデア（バックログ）

> MVP のスコープ外だが忘れたくないアイデア置き場。優先度は未定。実装する際は `/define-feature` で個別に要件化する。

## ボスのスキンをカスタマイズ

- ボスのアバターの見た目（キャラクターデザイン・服装・スタイル）を変更できる
- 人格カスタマイズ（口調・厳しさ）とは独立した「見た目」のカスタマイズ
- 検討事項: スキン素材の調達方法（プリセット同梱 / 画像アップロード / AI生成）

## ボス設定の export / import

- ボスの人格・スキン・運用設定（朝会夕会時刻など）をファイルとして書き出し・取り込みできる
- ユースケース: バックアップ、機材移行、他ユーザーと「ボス」を共有する
- 検討事項: フォーマット（JSON想定）、APIキー等の機密は含めない

## OS アクティビティ連携による自動サボり検知

- MVP のサボり検知（タスク操作＋チェックイン申告）を、アクティブアプリ・ブラウザ履歴等の OS シグナルで自動化・高精度化する
- 例: エディタ/ターミナルがアクティブ → 作業中と推定、SNS・動画サイトが長時間アクティブ → 脱線と推定
- 検討事項: 「全データはローカルのみ・外部送信は Claude API のみ」のプライバシー方針との整合（収集範囲・保存期間・LLM へ渡す粒度の設計が必要）。macOS の画面収録・アクセシビリティ権限
- 経緯: 2026-07-05 コンセプト深掘りで検討し、プライバシー設計の再検討が必要なため MVP では見送り

## 同僚とのブレイクタイム

- 休憩時間に「同僚」と雑談できる場を設ける
- 案A: AIが同僚キャラを演じる（ローカル完結、実装は容易）
- 案B: 実際の利用者同士がコミュニケーションできる（要サーバー・アカウント基盤・モデレーション。アーキテクチャがローカル完結前提から大きく変わるため要注意）
- 検討事項: MVPは完全ローカル・シングルユーザー設計のため、案Bはインフラ・プライバシー方針の再検討が必要

## 朝会での締切逆算（長期スケジュールの軽量サポート）

- 締切が近い・超過したタスクを朝会でボスが明示的に言及し、今日のタスク選定・優先順位に逆算で反映する
- タスクは既に `due_at` を持ち、ボスのコンテキストには全タスクの締切が毎回渡っているため、実装はほぼ朝会プロンプト（セッション指示）の調整のみで済む見込み
- 位置づけ: 長期プランナーを作るのではなく、「今日サボらせない」という核の価値を締切視点で強化する軽量対応
- 経緯: 2026-08-14 オーナー相談。フル機能のスケジュール管理はコンセプト（サボり検知・意思決定の外部化）を薄めるため YAGNI と判断し、まず本案を近い将来の候補とする。朝会で締切逆算がうまく働かない具体的な不便が出たら要件化する

## 外部ツール連携によるタスク取り込み（GitHub 等・保留）

- 外部ツール（GitHub Issues / Projects、カレンダー等）で立てた長期計画から、今日やる分を ai-boss のタスクへ取り込む（read-only インポート想定）
- 前提となる運用: 「計画は外部ツール、実行規律は ai-boss」の役割分担。取り込みは当面手動（またはボスに口頭で伝えてツールで作らせる）で回す
- 発動条件: 手動運用で「同じタスクの二重登録が苦痛」という実害が実際に発生したら検討を開始する
- 検討事項: 「全データはローカルのみ・外部送信は Claude API のみ」の不変制約に対し、新たな外部通信経路（トークン管理含む）を開く判断が必要。やる場合はこの制約の再検討込みで `/define-feature` で個別に要件化する
- 経緯: 2026-08-14 オーナー相談で「アプリ内スケジュール管理より外部連携が良いか」を深掘りし、上記の発動条件付きで保留と判断
