# ADR 0004: サボり検知は決定的なルールエンジンで行い、LLM は文面生成のみに使う

- **ステータス**: Accepted
- **日付**: 2026-08-20
- **関連**: 宣言元は退役した `docs/features/ai-boss-mvp.md`（クリティカル設計決定「サボり検知のシグナル源とエスカレーション」・機能全体の設計）。上位の制約は [ADR 0001](./0001-local-only-data-boundary.md)。閾値・エスカレーションの実際の振る舞いは `docs/guarantees.md`。

## 背景

本アプリの中核価値は「サボれない仕組み」であり、その実体は日中の未着手・回避・休憩延伸・無音を検知して段階的に催促することにある。

検知を LLM に任せる設計は一見自然に見える（「状況を渡して、サボっているか判断させる」）。しかしこの構造は次の問題を持つ: 判定が非決定的になり同じ状況で催促が出たり出なかったりする、閾値の仕様をテストで固定できない、毎分の評価ごとに推論コストが発生する、そして誤検知の原因を追跡できない。

催促は「無視され続けると強まる」性質を持つため、誤発火はユーザーの信頼を直接損なう。ここは再現性が要る領域である。

## 決定

1. **活動シグナルを `activity_events` テーブルに一元化**し、検知エンジンの**「活動シグナル」の単一入力**とする。明示チェックイン（`task_start` / `break_start` / `break_end` / `checkin`）に加え、チャット発言（`chat_message`）とタスク操作（`task_update`）をサーバーが自動記録する。**「ユーザーが動いたか」を表すシグナルを他のデータ源から取らない**という意味であり、検知エンジンが読む唯一のテーブルという意味ではない（決定 2 のとおり、判定にはタスク一覧・通知履歴・設定・当日のセッション種別も入力として渡る。[ADR 0005](./0005-sqlite-schema-policy.md) 決定 3 と同じ整理）。
2. **検知ルールエンジンは純粋関数として実装する。** 入力（タスク一覧・`activity_events`・設定・現在時刻）から出力（発火すべき催促のリスト）を決定的に導く。DB・現在時刻・LLM に副作用として触れない。
3. **発火判定に LLM を使わない。** LLM の役割は、発火が決まった後の**文面生成のみ**に限定する。
4. **エスカレーションは `rule_key` 単位で管理する。** 同一事由の催促は L1 → L2 → L3 と段階的に強まり、活動シグナルがあればリセットされる。重複送信防止も `rule_key` で行う。
5. **閾値はタスク粒度に適応させる。** 固定値ではなく、ユーザーが確認済みの所要時間見積もり（`tasks.estimated_minutes`）を基準にスケールさせ、上下限でクランプする。**見積もり未確認時のフォールバック値は設定で調整可能とする**（`detection_unstarted_fallback_minutes` / `detection_silence_fallback_minutes`）。**スケール係数とクランプ上下限（`scale` / `min` / `max`）は検知エンジンの組み込み既定値に固定し、設定からの上書きは行わない**（`server/src/scheduler/detection-settings.ts` に明記。設定画面へ露出する必要が生じた時点で `SettingKey` を追加して再検討する）。
6. **検知の抑制条件を持つ**（2 つのゲートは**例外の範囲が異なる**）:
   - **勤務時間帯外ゲート**: 検知ルールを**全件停止**する。例外は**朝会・夕会の定時催促のみ**で、**休憩延伸検知も停止する**。
   - **休憩ゲート（休憩申告中）**: 検知を停止するが、**休憩延伸検知はこのゲートの対象外**として動作させる。朝会・夕会の定時催促も対象外。

## 検討した代替案

- **LLM に状況を渡して発火を判定させる** — 却下。非決定的で再現性が無く、閾値仕様をユニットテストで固定できない。毎分評価のコストも見合わない。
- **タスク操作のみを活動シグナルにする（チェックイン無し）** — 却下。操作コストはゼロだが「長い集中作業」と「脱線」を区別できず、作業中の誤催促がノイズになる。休憩の延伸も検知できない。
- **OS アクティビティ（アクティブアプリ・ブラウザ履歴）を使う** — 見送り。検知精度は最高だが [ADR 0001](./0001-local-only-data-boundary.md) の再設計が必要。
- **固定閾値にする** — 却下。5 分のタスクと 3 時間のタスクに同じ無音許容時間を当てると、どちらかで必ず破綻する。

## 帰結

- 検知ルールの閾値・エスカレーション段階はユニットテストで仕様を固定できる。時刻はモックする。**暦日の区切りに関わるテスト**はタイムゾーン非依存に書く（[ADR 0007](./0007-local-calendar-day-basis.md) 決定 5。検知ルールの多くは経過時間のみを扱うため、そこでは UTC リテラルで固定してよい）。
- 新しい活動シグナルを追加する場合は `activity_events` の種別追加として実装する。検知エンジンに新しい入力経路を足さない。
- 「ボスが賢く判断してくれる」体験は、発火判定ではなく**文面**で作る。文面生成が失敗しても催促自体は送る（best-effort）。
- スケジューラは毎分チェック方式で、この純粋関数を呼ぶ薄い層として実装する。
